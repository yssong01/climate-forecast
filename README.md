# Tri-CHEF Climate Forecast

3축(위성 이미지 · 기상 문서 · 수치 센서) 멀티모달 융합으로 기상청 ASOS 관측 데이터를 기반으로 +6시간 기온·강수를 예측하는 실험 프로젝트입니다.

논문 **Tri-CHEF**(검색 태스크용 Hermitian 스타일 3축 융합, `s = √(A² + (αB)² + (φC)²)`)의 수식 구조를 기후 예보 도메인에 적용하고, 그 과정에서 발견한 문제들을 수식·코드·ablation 실험으로 추적한 기록입니다.

## 결과 요약

+6시간 예보, 12개 관측소(서울·인천·수원·춘천·강릉·대전·청주·전주·광주·대구·부산·제주) 통합 학습, 검증셋 1,709개 기준.

| 지표 | 모델 | baseline | 개선 |
|---|---|---|---|
| 기온 MAE | 0.85 °C | 퍼시스턴스(T(t+6)≈T(t)) 2.73 °C | **+69.0%** |
| 강수 MAE | 0.30 mm | 상시 0 예측 0.36 mm | **+15.3%** |

동적 게이팅 네트워크가 학습한 축 배분: **수치 센서 92% · 기상 문서 5% · 위성 이미지 2%** (아래 [한계](#정직한-한계) 참조 — 이 배분에는 이유가 있습니다).

## 아키텍처

```
                    ┌─────────────┐
   위성 이미지  ───▶ │ Re 인코더    │──┐
   (4ch, 32×32)     │ (소형 CNN)   │  │
                    └─────────────┘  │
                    ┌─────────────┐  │    ModalityGate
   기상 예보문  ───▶ │ Im 인코더    │──┼──▶ (입력 조건부    ──▶ s = √(w_re·A² + w_im·B² + w_z·C²)
   (MiniLM 384d)    │ (프로젝션)   │  │     softmax 배분)          │
                    └─────────────┘  │                             ▼
                    ┌─────────────┐  │                    ┌───────────────┐
   ASOS 수치(12d) ─▶ │ Z 인코더     │──┘                    │ 기온·강수 헤드 │
                    │ (MLP)       │                        └───────────────┘
                    └─────────────┘
```

- **Re축**: 4채널(R/G/B/NIR) 합성 위성 이미지 → 소형 CNN (2.8만 파라미터)
- **Im축**: 기상청 스타일 한국어 예보문 → `paraphrase-multilingual-MiniLM-L12-v2` (384d) → 프로젝션
- **Z축**: 기온·강수·습도·풍속·풍향(sin/cos)·기압·강수형태·시각(sin/cos)·위도·경도 (12차원) → MLP
- **융합**: Eq.1 Hermitian-style modulus. 축 가중치는 정적 학습 파라미터 또는 입력 조건부 동적 게이트(`ModalityGate`) 중 선택 가능
- **예측**: 기온은 퍼시스턴스 잔차(Δ) 방식, 강수는 softplus 헤드로 항상 양수 보장

## 실행

```bash
pip install -r requirements.txt      # 아래 "환경 주의사항" 먼저 읽어주세요
cp .env.example .env                 # KMA_API_KEY 발급 후 입력 (apihub.kma.go.kr)

python test_phase34.py               # 수치 안정성 19개 항목 검증
python train.py                      # 12개 관측소 수집(~40분) + 학습
python predict.py --stn 108          # 단발 추론 (CLI)
streamlit run app.py                 # 실시간 대시보드
```

`predict.py --list-stations`로 관측소 코드 목록 확인 가능.

### Docker로 대시보드만 실행

학습은 로컬 GPU 환경에서 미리 마쳤다고 가정한다 — 이미지에는 체크포인트를
포함하지 않고 런타임에 볼륨으로 마운트한다(`Dockerfile` 상단 주석 참고).

```bash
docker build -t tri-chef-app .
docker run -p 8501:8501 \
  -v "$(pwd)/checkpoints:/app/checkpoints" \
  -v "$(pwd)/cache:/app/cache" \
  --env-file .env \
  tri-chef-app
```

CI(`.github/workflows/ci.yml`)는 push/PR마다 수치 안정성 19개 항목
(`test_phase34.py`)과 Dockerfile 빌드를 자동 검증한다.

## 정직한 한계

이 프로젝트는 "만들고 나서 잘 됐다"가 아니라, **잘못된 것을 실험으로 잡아낸 기록**에 가깝습니다. 채용 담당자나 리뷰어가 이 프로젝트의 신뢰도를 판단할 때는 성공한 숫자보다 아래 항목이 더 의미 있다고 생각합니다.

### 1. 시뮬레이션 모달리티는 실제 정보를 추가하지 않습니다

Re축(위성)과 Im축(텍스트)은 현재 **Z축 수치에서 결정론적으로 생성한 시뮬레이션**입니다(`satellite_collector.py`, `text_collector.py`). Ablation 결과, 게이트는 데이터가 12배(572→6,837 표본)로 늘어나자 오히려 두 축의 배분을 더 낮췄습니다(11%→7% combined). 이는 "데이터가 적어서 게이트가 잘못 판단했다"는 가설을 반증하며, 두 축이 구조적으로 Z축과 같은 정보를 재인코딩할 뿐이라는 뜻입니다. Sentinel-2 실위성·기상청 실제 예보문을 연결하기 전까지는 멀티모달 아키텍처 자체의 가치를 이 프로젝트로 입증했다고 말할 수 없습니다.

### 2. Gram-Schmidt 직교화는 이 도메인에서 손해였습니다

논문은 검색 태스크에서 축 독립성(직교성)을 전제하지만, 실측(`ablation.py`)에서 직교화를 강제하면 성능이 하락했습니다. 네트워크가 자유롭게 학습한 Re-Im 상관도(0.48)가 오히려 회귀 성능에 기여하고 있었습니다 — 축 간 정보 공유가 강건성으로 작용하는 회귀 태스크와, 독립성이 곧 변별력인 검색 태스크는 다릅니다. 기본값은 `ORTHOGONALIZE = False`로 되돌렸습니다.

### 3. 정적 축 가중치는 무용한 축을 억제하지 못했습니다

학습 가능한 α/φ(log-parameter)는 정보가 없는 위성 축의 가중치를 오히려 키웠습니다(α 0.4→0.665). 원인은 두 가지: (a) 논문 기본값 자체가 위성 축을 1순위로 두는 초기화였고, (b) ResNet18(1,100만 파라미터)이 학습 표본(572개)을 그대로 암기해 훈련 손실 기준으로는 "가장 잘 맞는 축"으로 보였기 때문입니다. `ModalityGate`(균등 초기화 + 엔트로피 정규화 워밍업) + 인코더 축소(2.8만 파라미터)로 이 문제를 해결했습니다.

### 4. 1시간 예보는 무의미했습니다

1시간 후 기온은 퍼시스턴스(T(t+1)≈T(t))가 사실상 무적이라 어떤 모델도 유의미한 개선을 보여줄 수 없었습니다(+0.7%). 예보 시계를 6시간으로 늘리자 시각(일주기) 특성과 축 융합이 실제로 기여하기 시작했습니다(+69%). 변수마다 예측 가능 시계가 다르다는 것을 보여주는 결과이기도 합니다 — 같은 6시간 시계에서 기온은 +69% 개선됐지만 강수는 +15%에 그쳤습니다(대류성 강수는 지상 관측만으로 예측 가능 시계가 짧습니다).

### 5. 이 프로젝트 자체의 디버깅 과정에서 잡은 실제 버그들

- `torch.clamp(x, 0, 200)`이 x<0에서 gradient가 정확히 0이 되어, 강수 예측 헤드가 전 샘플 음수로 수렴한 뒤 영구히 학습 정지 (`softplus`로 교체)
- 기온 손실(σ²≈수십 규모)이 강수 손실(O(1))을 1000배 압도해 강수 헤드가 사실상 학습되지 않음 (분산 정규화)
- baseline을 검증셋이 아닌 전체 데이터에서 계산해 표본 불일치로 인한 허위 "개선"이 발생 (검증셋 동일 표본으로 수정)
- 다중 관측소 확장 시 관측소 경계에서 서울 관측값과 부산의 6시간 후 관측값이 우연히 페어링될 수 있는 경로 존재 (관측소 코드 일치 조건 추가로 원천 차단)
- 테스트 스크립트가 실패 항목을 출력만 하고 종료 코드 0을 반환해, **CI가 어떤 항목이 깨져도 항상 초록불**이었음 (`sys.exit(0 if n_pass == n_all else 1)` 추가). 테스트를 CI에 붙이는 것과 CI가 테스트 결과에 반응하는 것은 별개였습니다.

## 환경 주의사항

이 저장소의 `requirements.txt`를 전역 Python 환경(venv 미사용)에 설치하면 `numpy<2`, `pillow<11` 등 Streamlit의 의존성 제약 때문에 **같은 환경의 다른 프로젝트가 깨질 수 있습니다.** 가상환경 사용을 강력히 권장합니다.

```bash
python -m venv .venv
.venv\Scripts\activate      # Windows
pip install -r requirements.txt
```
